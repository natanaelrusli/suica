# Idea Box Implementation Plan

## Goal

The Owner can capture an unfinished thought immediately, find it later, and brainstorm one or more saved ideas with their existing Coding Agent. Capture works offline and never starts a model run.

## Product decisions

- Add **Idea Box** under Work in the native macOS app, plus a quick-capture action in the menu bar popover.
- Capture requires only text. No mandatory title, folder, project, tags, or priority. Display the first non-empty line as the list title; retain the full text unchanged.
- Support personal ideas as well as project ideas. An optional project folder is context, not an eligibility requirement.
- Start with two states: Inbox and Archived. Brainstorming does not automatically archive an idea or turn it into a task.
- Use the Owner's existing Coding Agent for brainstorming. Do not add an embedded model provider, credentials, background ideation, or a second chat system.
- Always offer **Copy brainstorm prompt**. Offer **Brainstorm in Office** for a supported, idle live Session. This makes the feature useful without a running agent while reusing native conversation display when one exists.
- AI output never silently replaces captured text. The Owner can save selected conclusions as an idea note and link a resulting plan.

## Existing integration seams

- `src/store.ts`: SQLite schema and store lifecycle. Follow the dedicated sub-store pattern used by `src/lesson-store.ts`.
- `src/cli.ts`: command routing, stdin input, JSON responses, and Office commands.
- `src/office/send.ts`: sends to live Claude Code, Codex, and Gemini Sessions; rejects working Sessions and messages over 8,000 characters. Runs under the Owner's existing agent permissions.
- `src/office/chat.ts` and the Office app surface: existing conversation reading and display.
- `macos/Suica/Sources/Suica/Navigation.swift`: window sections and shortcuts; preserve existing shortcuts.
- `macos/Suica/Sources/SuicaCore/AgentClient.swift`: native app-to-CLI integration.
- `macos/Suica/Sources/Suica/Window/MainWindow.swift` and `MenuView.swift`: page and quick-capture entry points.
- `README.md` and `CONTEXT.md`: user-facing behavior and vocabulary.

New filenames below are proposed, not existing APIs.

## 1. Persistence and CLI

- [x] Add an Idea sub-store in `src/idea-store.ts`, attached through the existing Store lifecycle.
- [x] Add an additive SQLite migration without altering existing review, lesson, or fix data.
- [x] Store idea id, text, optional project path, created/updated timestamps, archive timestamp, and revision. Keep notes separately, with their own timestamps, so conclusions do not overwrite the original idea.
- [x] Store optional links to brainstorm Sessions and local plan paths. A Session link is a reference, not a durable copy of its transcript; ideas and notes must remain readable if that transcript disappears.
- [x] Implement create, list/search, show, edit, archive, restore, add note, and link operations. Search idea text and notes; exclude archived items by default. Use simple SQLite queries initially, not a vector index.
- [x] Use revision checks for content edits so two app/CLI clients cannot silently overwrite each other. Report conflicts while preserving the unsaved draft.
- [x] Add `suica ideas` commands with JSON output. Read captured text and mutation payloads from stdin, not shell-interpolated arguments.
- [x] Define `contracts/ideas.v1.json` alongside the TypeScript implementation and Swift decoders. Specify size limits, ordering, missing-id errors, revision conflicts, and empty-input behavior.
- [x] Test actual persistence across reopen, search including notes, archive/restore, conflicting edits, and preservation of existing data during migration.

**Acceptance:** A text-only idea can be saved and retrieved while offline and while the background agent is stopped. Failed writes never show a successful capture.

## 2. Native capture and retrieval

- [x] Add Swift models/client operations following the existing app-to-CLI pattern, and an Idea Box page with Inbox/Archived filters, search, list, and detail editor.
- [x] Add a menu bar **Capture idea…** action opening a focused multiline composer. A shortcut submits; ordinary Return inserts a newline.
- [x] Keep the composer open with its text intact on write failure. Close and clear it only after successful persistence; prevent double submission while saving.
- [x] Show original text, optional project, notes, and linked discussions/plans in the detail pane. Provide explicit Save, Archive, and Restore actions.
- [x] Protect unsaved edits when changing selection or closing the editor.
- [x] Provide selection of multiple ideas for one brainstorming prompt, without merging or changing the originals.

**Acceptance:** The Owner can open quick capture, paste an unstructured thought or URL, save it without metadata, restart Suica, and find/edit it. Cancelling or encountering an error does not silently discard a draft.

## 3. Brainstorm handoff

- [x] Add a deterministic prompt builder in `src/ideas/brainstorm.ts` shared by copy and Office handoff paths.
- [x] Include the selected idea ids and exact saved text, optional notes/project context, and an optional question from the Owner. Delimit captured material as reference content rather than executable instructions.
- [x] Default the request to: clarify the underlying problem, ask only material questions, explore alternatives and tradeoffs, challenge assumptions, and propose the smallest useful experiment. Ask for discussion only, not code changes or external actions.
- [x] Preview the exact prompt before handoff. Let the Owner choose a supported idle Session and show its project folder; warn if it differs from the idea's project.
- [x] Use the existing Office send/read paths, then navigate to the chosen Session's Chat Panel for continued discussion. Do not duplicate transcripts in Idea Box.
- [x] Check the complete rendered prompt against the existing 8,000-character Office limit. Never silently truncate ideas: offer the full copyable prompt and ask the Owner to narrow the Office selection instead.
- [x] Preserve selection and prompt on busy, missing Session, missing CLI, timeout, or other failure. Do not automatically resend: a failed process may already have delivered part of a turn.
- [x] Explain that a discussion-only prompt is guidance, not a sandbox: the resumed agent retains its existing permissions and conversation context. Do not advertise this as enforced read-only execution.
- [x] Record a Session reference after successful handoff. If it is no longer available later, keep the idea usable and offer Copy brainstorm prompt again.

**Acceptance:** With an idle supported Session, selected ideas reach the agent intact and the conversation appears in Office. With no Session, the Owner can copy the same prompt into any agent and continue there.

## 4. Keep useful outcomes

- [x] Add **Save note** to an idea so the Owner can paste or write conclusions, decisions, open questions, and next experiments without changing the captured thought.
- [x] Add **Link plan…** for an existing local Markdown plan. Open the linked file using existing local-file conventions; a missing file is an explicit unavailable link, not a reason to lose the idea.
- [x] Document how the Owner can ask their Coding Agent to write a dated Markdown plan into a folder already scanned by Suica's Plans page, then link it to the idea. Do not add another plan tracker or automatically mark a plan done.
- [x] Allow an idea to stay in Inbox after brainstorming, or be archived explicitly.

**Acceptance:** A saved note and plan link survive restart independently of the agent Session. The Owner can return from a plan to its originating idea through the Idea Box record.

## 5. End-to-end proof and documentation

- [x] Exercise the real CLI against a temporary state database: capture, restart/read, search, edit, archive, restore, save note, and link a plan.
- [ ] Exercise the actual macOS surface: quick capture, multiline text, save failure, unsaved edits, filtering, selection, and reopening a stored idea.
- [ ] Perform one real handoff to an installed supported Coding Agent and observe the prompt and response in Office. Also exercise no-session copy and busy-session rejection. If no agent is available, report that verification prerequisite rather than treating a mocked send as proof.
- [x] Keep regression tests for migration preservation, lost-update conflicts, note/original separation, prompt fidelity and length boundaries, and failure behavior. Use existing test conventions; do not test incidental copy or forwarding alone.
- [x] Run the repository's existing TypeScript and Swift checks after integration.
- [x] Update README, CONTEXT vocabulary (Idea, Idea Box, Brainstorm), and the JSON contract with shipped behavior and permission/privacy limits.

## Privacy and scope boundaries

Ideas may contain sensitive material. Keep content in the existing local state database; do not log idea text or brainstorm prompts. Explain before handoff that the selected agent may send the prompt to its configured provider. No model or network request is required to capture, search, edit, or archive.

Not included: cloud sync, collaboration, attachments/voice capture, automatic tagging, embeddings, reminders, autonomous idea execution, new agent-session creation, MCP installation, or a new model-provider integration. Revisit only when ordinary capture and explicit handoff are insufficient.

## Stop condition

The Owner can capture without friction, retrieve an idea after restart, brainstorm it through Office or a full copyable prompt, and preserve the useful outcome as a note or linked plan. No model runs or external actions happen merely because an idea was saved.
